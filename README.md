# まちづくりAI

## プロジェクト概要
- **名称**: まちづくりAI
- **目的**: 対象エリアの現況写真に対し、ユーザーの要望に沿った建造物・広場の画像をAIが生成するSPA。現地に施設が入るとどう見えるかを可視化する
- **主な機能**:
  - 6問チャットで施設・利用シーン・スタイル・周囲環境・季節/時間帯・追加要素を収集
  - GPT-4.1-mini で日本語→英語プロンプト最適化
  - fal.ai NanoBananaPro (nano-banana-pro/edit) で画像生成（ポーリング方式）
  - Canvas による元画像との合成（上部の背景を元画像で保持）
  - 元画像 / 生成結果をタブで切り替え表示
  - ダウンロード・やり直し機能
  - PWA対応（ホーム画面に追加可能）
  - スマートフォン最適化（safe-area・min-height 44px）

## URL
- **本番**: https://machizukuri-ai.pages.dev/
- **サンドボックス**: http://localhost:3000
- **プレビュー**: 本番以外のブランチ名でデプロイすると `https://<ブランチ名>.machizukuri-ai.pages.dev` で確認できる（例: `set6-test`）。本番には影響しない
- **画像セットの指定**: `?set=N`（N=1〜7）。パラメータなしの既定はセット4（`config/image-set.json`）。例: `https://machizukuri-ai.pages.dev/?set=6`

| `sceneDescription` | string | 元画像の場所説明。systemPrompt の背景情報に展開される |

| `edgeTreatmentRule` | string | エッジ処理ルール。柵の有無など。systemPrompt ルール6に展開される |

| `compositeIgnoreSkip` | string[]（任意） | `shouldSkipComposite` の判定語のうち、そのセットでスキップ判定から除外する語。セット6は アーケード・ドーム・大屋根・天蓋・屋根で覆・屋根が覆・ガラスの屋根・提灯・ちょうちん。未指定は除外なし |

### maskMode による挙動の違い

**`'white'`（セット1・2・5）**  
白く塗りつぶしたマスク画像を fal.ai に送り、白い範囲を生成対象として扱う。`buildPrompt()` の冒頭は「マスクした白のエリアを〜」となり、systemPrompt にも「白い範囲が変更対象です」という説明が入る。

**`'none'`（セット3・4・6）**  
加工していない元画像をそのまま送る。`fal-ai/nano-banana-pro/edit` は `mask_url` を受け付けず画像全体を描き直すため、白塗りは「白い物体」として解釈されるおそれがある。そのため領域指定は白塗りではなく次の2層で行う。

1. **プロンプトによる領域指定** — `maskAreaDetail` に保持すべき背景要素を列挙し、生成対象を自然言語で指定する。`white` / `mask` といった語の使用を明示的に禁止する
2. **Canvas合成による背景保持** — 生成結果の上部を元画像で上書きし、空・山稜線・建物上層を確実に保持する

`buildPrompt()` の冒頭は `maskAreaLabel`（セット4なら「広場のエリア」）に切り替わり、「マスク」「白」という語は draftPrompt に一切含まれない。

## Canvas 合成の仕組み

`app.js` の `compositeWithOriginal()` が、生成画像の上部を元画像で置き換える。

```
cutY      = 生成画像の高さ × compositeCutRatio
feather   = compositeFeatherRatio があれば 高さ × 比率（最小12px）、なければ 60px
fadeStart = cutY - feather / 2
fadeEnd   = cutY + feather / 2

y <= fadeStart            → 元画像 100%
fadeStart < y < fadeEnd   → 線形αブレンド
y >= fadeEnd              → 生成画像 100%
```

セット4（生成画像 1376×768）の実測値は cutY=269 / feather=38 / fadeStart=250 / fadeEnd=288。屋上サイン（y≈80〜100）と山稜線（y≈200）はいずれも fadeStart より上にあり、元画像100%の領域で保持される。

`compositeCutRatio` を大きくすると背景の保持範囲が広がる一方、生成物の上端が水平に切り落とされやすくなる。高い構造物が切れる場合は値を下げる。

### セットごとのパラメータ受け渡し

`src/index.tsx` が HTML に以下のインラインスクリプトを出力し、`app.js` 読み込みの**前**にセット情報を渡す。

```html
<script>
  window.__IMAGE_SET__ = {
    setId: 4,
    originalUrl: '/static/images/004-motogazou-kisera-1700x956.jpg',
    compositeCutRatio: 0.35,
    compositeFeatherRatio: 0.05,
    maskMode: 'none',
    maskAreaLabel: '広場のエリア',
    compositeEnabled: true
  };
</script>
<script src="/static/app.js"></script>
```

セット6では、上記に加えて任意項目 `compositeIgnoreSkip` / `compositeTimeOfDaySkip` / `timeOfDayNote` / `conceptEnabled: true` が出力される（定義があるセットのみ。セット1〜5には出力されない）。`setId` は `?set=` の解決結果で、`app.js` が `/api/refine-prompt` と `/api/generate-submit` に送る。

画像URLの基点は、アクセス元が `machizukuri-ai.pages.dev` またはそのサブドメイン（プレビュー）で https の場合はそのオリジン、それ以外は本番URLになる（`resolveImageBaseUrl`）。プレビューでは、そのプレビュー自身の画像を fal.ai に渡す。

`app.js` はトップレベルで `COMPOSITE_CUT_RATIO` を評価するため、この順序が逆になると設定が読まれずフォールバック値（0.30）が使われる。インラインスクリプトの構文エラーでも同じ事故が起きるため、変更時はブラウザのコンソールでエラーがないことを確認すること。

### 合成のスキップ

夜景・夕景・花火・ドローンショー・大屋根など、画像上部が元画像と大きく変わる指定があった場合は `shouldSkipComposite()` が働き、合成せず生成画像をそのまま表示する。判定語は `NIGHTTIME_KEYWORDS` と `SKIP_KEYWORDS_EXTRA` に定義。`SKIP_EXTRA_ENABLED = false` にすると拡張リストが無効化され、「雨」「曇り」を含む旧挙動に戻る。

**セット別の調整（セット6のみ。引数を省略するセット1〜5は従来と完全に同じ挙動）**

`shouldSkipComposite(text, ignoreWords, timeOfDayOnlyWords)` は、セット設定から次の2つを受け取る。

- `compositeIgnoreSkip`: スキップ判定の語から除外する語。セット6は、アーケード入口そのものが元画像にあるため「アーケード」「ドーム」「大屋根」「天蓋」「屋根で覆」「屋根が覆」「ガラスの屋根」「提灯」「ちょうちん」を除外する
- `compositeTimeOfDaySkip`: 「季節・時間帯:」で始まる行に限って判定に加える語。セット6は「朝」「早朝」「朝方」「雨」「曇り」「雪」。他の行（例:「朝市」「雨宿り」）にこれらの語があってもスキップしない。`timeOfDayNote` の行は「季節・時間帯:」で始めないため、この判定の対象外

デバッグ用に `COMPOSITE_ENABLED = false` とすると、合成前の生の生成結果を確認できる。

## セット6（サカエマチ2番街）の仕様

池田市「ショッピングシティ サカエマチ2番街」のアーケード入口（シャッターが閉まった商店街）を、ユーザーの回答に沿った新しい商店街のイメージに変えるセット。看板の下の通路・店先・床だけを作り替え、看板・照明・屋根・支柱・カメラは元画像のまま保つ。

### 方式
- `maskMode: 'none'`（元画像をそのまま fal.ai に渡す）、`aspectRatio: '5:4'`、`compositeCutRatio: 0.46`、`compositeFeatherRatio: 0.04`
- 夜・夕方・朝・雨・曇り・雪など、空や光が大きく変わる指定ではCanvas合成をスキップし、生成画像をそのまま表示する（「合成のスキップ」参照）
- `maskAreaLabel`（日本語ドラフトに入る）には、スキップ判定語を含めない

### 英語プロンプトの組み立て
`/api/refine-prompt` は、次の3つをサーバー側で連結して返す。

```
promptPrefix（約115語・固定）+ LLMが書く中間部分（66語以内）+ promptSuffix（約90語・固定）
```

| 部分 | 内容 |
|---|---|
| promptPrefix | 写実の指定、元画像と同一のカメラ位置・視点の高さ・画角、緑の看板（横幅の約9割・下端が画像高さの約4割）と2つの照明の保持、透明なアーチ屋根・骨組み・緑の支柱の保持 |
| 中間部分（LLM） | 時間帯・空・光 → 施設・スタイル・床の素材・人物 → 回答に空の演出があれば、その演出。固定文と重複する内容は書かせない |
| promptSuffix | 地上に足す要素は屋根の下かつ看板の下端より下に収める、**看板の面と文字には何も重ねない（光の筋・にじみ・火花・飾りを含む）**、店舗の庇・壁・窓は無地で、看板の日本語だけが文字、コラージュ・境界線なし、写実（アニメ・イラスト・CGではない） |

固定文を連結する分、LLMの中間部分は66語以内とし、合計260語前後は目安として扱う（回答の反映を優先する）。

### 空・光・空の演出
- 時間帯・天候の指定があれば、空の色と全体の光を指定に合わせて変える。指定がなければ元画像の昼間の空と光のままにする
- 雨・曇り・雪は、空・光・雰囲気の表現に限る（路面の濡れや積雪は描かない）
- **空の演出（星・月・光の演出・花火など）は、ユーザーの回答に明記されている場合だけ描く。** 「こだわりなし」「特になし」など回答にない場合は、空に何も足さず、時間帯による空の色と光の変化だけにする
- 回答にある場合も、屋根の外に見える狭い空（看板の上端より上と、看板の左右の外側）だけに小さく描き、看板の面・文字・2つの照明の上には重ねない。空を広げるために看板を縮める・画角を引く・屋根を消すことは禁止
- 屋根の透明部分や路面に演出の色が映ることを許可する文は置かない（看板に光がにじむ原因になるため。以前はこの許可文があった）

### その他の制約（日本語の指示としてsystemPromptに入れる）
- 看板は元の色（緑）のまま。時間帯による光の色味の変化だけ許可する
- 樹木は鉢植え・低木、または屋根の下端より低いものに限る。芝生などの床の指定は、屋根の下の通路の床の範囲に限る
- 店舗の庇・看板・のぼり・壁・窓・メニューなどに文字・英単語・数字・ロゴ・店名を描かない
- 施設名の直前に様式の形容詞（レトロ・モダン・和風など）を付けず、素材・色・形・照明で表す。「公園」「広場」など屋外の場所を表す語を場所の名前として書かず、通路に置く設置物として表す

### systemPrompt を書くときの方針（重要）
- **英語の見本文や具体例を書かない。** gpt-4.1-mini は「回答がある場合のみ」といった条件を守らず、systemPrompt にある英語文や具体例を、回答になくても出力に写すことがある（例: 回答に花火がないのに fireworks が出力された）
- セット6の systemPrompt（`maskAreaDetail`・ルール上書き）には、「花火」「firework」「effect」を入れない。空の演出は「回答の語を使う」という日本語の指示だけで書かせる
- 英語として残してよいもの: ルール10の時間帯の例（`an orange-to-purple dusk sky` など）、ルール12の例（`a cafe counter with dark wood paneling…` など）、芝生指定時の文、`the arcade street and its shopfronts`。なお promptSuffix の禁止文には `effects` が入るが、これは systemPrompt には入らない
- 固定文（promptPrefix / promptSuffix）で言う内容は、systemPrompt では日本語で「固定文に含まれるので英語では書かない」と指示する。同じ英語文を systemPrompt に置くと、中間部分に重複して出力される

### 変更時の確認手順
1. 共通部分（`src/index.tsx` の共通ルール、`app.js`）を変えた場合は、変更前後でセット1〜5のHTML・systemPrompt・API応答が一致すること、スキップ判定の全組合せが一致することを確認する
2. 組み立て後のセット6の systemPrompt（通常・夕暮れ）と promptPrefix に、「花火」「firework」「effect」が0件であることを文字列検索で確認する
3. ビルド後、プレビュー（別ブランチ名）にだけデプロイし、`/api/refine-prompt` を1パターン1回ずつ確認する（春の昼間・夏の夕暮れ・冬の夜＋花火・冬の朝）。空の演出は回答にある場合だけ出ること、看板の上と左右の外側の空に限定されることを見る。LLMは非決定的なため、問題が出やすいパターンは複数回確認する
4. 画像生成の結果は、プレビューの `?set=6` で人が確認する

## セット6（質問文の変更）

### set-text.js の役割
- `public/static/set-text.js` は、`index.tsx` が辞書 `window.__SET_TEXT__` を埋め込んだセット（=セット6）だけ、`app.js` の後に読み込まれる共通ローダー。辞書がないセット（1〜5・7・既定）ではファイル自体を読み込まず、HTMLはベースラインとバイト一致する

- 辞書の項目: `questions`、`q2Fixed`、`noneWords`、`summaryLabels`、`draftLabels`、`draftLine1` / `draftLine1None` / `draftLine5`、`extraSkip { hang, tall, event, lamp, strip }`

### 合成スキップ判定に足した語
セット6は、生成画像の上部（看板より上）を元画像に貼り戻す合成を行う（看板下端 y=258、cut 0.46、feather 0.04）。回答に次の語があると合成をスキップし、生成画像をそのまま表示する。判定対象は下書き全体。`app.js` の `NIGHTTIME_KEYWORDS` と `SKIP_KEYWORDS_EXTRA` による従来の判定はそのまま残る。
- `hang`（頭上に吊る飾り）29語: 吊る・吊り・吊し・ぶら下・提灯・屋根から・天井から など
- `tall`（背の高い物）13語: 時計台・時計塔・タワー・ツリー・笹・七夕飾り・鯉のぼり・風車・観覧車・ゲート・アーチ・大木・巨木
- `event`（行事）7語: クリスマス・正月・七夕・ハロウィン・年末年始・初詣・端午
- `lamp`（灯り）5語
- `strip`: 「のぼり旗」「ノボリ旗」「幟旗」は、判定の前に取り除く（ノボリ自体はスキップ理由にしない）
- 判定は hang → tall → event → lamp の順

### 時間帯語がないときの「時間帯の反映:」行
Q5（時間帯・季節・行事）の回答に時間帯語（`TOD_WORDS` 62語＋辞書の lamp 5語）がないときだけ、systemPrompt の「時間帯の反映:」行（`W.timeOfDayNote` と完全一致する行）を、次の固定文に差し替える。
> 時間帯の反映: 時間帯の指定はない。行事や季節の飾りだけを加え、空の色と明るさ、全体の光は元画像と同じ昼間のままにする。空には天体を描かない。

あわせて、systemPrompt に追加する文を回答に応じて3つに分ける。
1. 回答に行事語（`eventWords` 7語）がある → 追加文は足さない
2. 行事語はないが、hang / tall の語がある → 「季節の行事の飾りは加えない。」
3. どちらもない → 「季節の行事の飾りや、屋根の下・頭上の飾りは加えない。」

ひらがなの時間帯語は、あけがた・よあけ・ゆうがた・ゆうぐれ・ゆうやけ・しんや・よぞら・くもり（3文字以上）だけを対象にする（短いひらがなは誤判定しやすいため）。

### rule10 の行事例文を回答にある行事だけに絞る
systemPrompt の rule10 に行事の「描き方の例」（クリスマス・お正月・七夕）があると、クリスマスの回答でもお正月の飾りが出る問題があった。そこで、ハンドラが回答（下書き）の行事語を見て、rule10 を次のように組み替える（`rule10Event` / `eventWords`、定数 `SET6_RULE10_*`）。
- **行事語なし**: 例文のブロックだけを外す。「季節だけ（冬・春など）で行事名がない場合は…加えない」の文は残す
- **行事語あり**: 「季節だけ」の文を外し、「回答に行事の指定があるときは、その行事の飾りを必ず1つ以上入れる。回答にない行事の飾りは入れない。」を足し、下書きにある行事の例文だけを残す
  - クリスマス → クリスマスの例のみ / 正月・年末年始・初詣 → お正月の例のみ / 七夕 → 七夕の例のみ
  - ハロウィン・端午だけのときは、例文ブロックごと外す
- 置き換え対象が systemPrompt 内にちょうど1か所でないときは、systemPrompt を変えずにエラーログを出す

### 暴走ガード（`refineGuard`）
LLMが中間部分（66語以内の依頼）を異常に長く出力する事象（716語など）への対策。セット6の `/api/refine-prompt` だけが通る。
- 検出: 中間部分が空白区切りで **100語超**、またはカンマ区切りの同じ句（trim・小文字化）が **3回以上**
- 検出したら、同じ呼び出しを **1回だけ再試行**する
- 再試行でもなお異常なら、重複を1つにまとめ（最初の出現を残す）、カンマ位置で **70語以内に切り詰める**。先頭の句だけで70語を超える、またはカンマがない場合のみ、語単位で切る。再試行がHTTPエラーのときは、1回目の出力を切り詰める
- ログ: `console.log('[refine-guard] set 6: ...')` に理由と処理前後の語数を出す
- 応答の形 `{success, refinedPrompt}` は変わらない

### crowdSentence と crowdOffWords
通りがさびしく見えないよう、固定文 `crowdSentence`（約77語）を最終プロンプトに足す。
- 最終プロンプト = `promptPrefix` + LLMの中間部分 + `crowdSentence`（条件付き）+ `promptSuffix`
- `crowdSentence`: 回答にある人物のほかに、年齢の違う買い物客や通行人が離れた位置を歩き、店先に数人が立つ、にぎやかだが混みすぎない雰囲気にする。人物は足元（画像の上から48%より下）に自然な大きさで立ち、緑の看板と2つの投光器の前には出さない。48%は合成の境目（高さ620pxの285px=46%、ぼかし25pxで44〜48%）を考慮した値
- ガードの後に連結するため、100語の判定には含まれない
- **`crowdOffWords`（17語）**: 下書き（6問の回答）にこのどれかがあるときは `crowdSentence` を連結しない。静か・しずか・ひっそり・閑散・人がいない・人けのない・人気のない・誰もいない・無人・ひとり・一人・独り・貸切・少人数・人が少ない・人通りの少ない・まばら
  - 「ゆっくり」「のんびり」は含めない。「一人ひとり」は誤判定する（人を増やさない側の誤り）

## セット7（川西の店舗前）の仕様
2階建て店舗（瓦屋根・ピンクの外壁）の前の駐車場を、6問の回答に沿った新しい空間に作り替える。セット6と同じく、日本語の指示と固定文（`promptPrefix` / `promptSuffix`）で構成する。

- **画像**: `original` は `007-motogazou-store.jpg`（元は1024×578。上下1pxずつを切り落として1024×576、JPEG 品質95・4:4:4。拡大なし）。`mask`（fal.ai に送る画像）は、左右の置物を画像加工で消した `007-motogazou-store-clean.jpg`（同じ1024×576・4:4:4）。理由は後述「クリーン画像を mask に使う理由」
- **設定**: `maskMode: 'none'`、`compositeEnabled: false`（貼り戻し合成なし）、`aspectRatio: '16:9'`、`conceptEnabled: true`、`conceptPlace: '川西の店舗前'`、`conceptTheme: 'store'`
- **`maskAreaLabel`**: 「店舗前の駐車場のエリア」（`shouldSkipComposite` の判定語を含まない）
- **作り替える範囲**: 手前の駐車場。置物はクリーン画像の時点で消えているため、プロンプトでは撤去を指示しない。地面の言い方は施設に応じて分ける（後述「地面の書き方（asphalt 対策）」）
- **店舗**: 取り壊さず、形・色・位置・大きさを変えない。手前の物の後ろに元のまま建つように描く。手前の物が重なって店舗の一部または大部分が隠れてもよい（生成物の大きさに上限なし）
- **残すもの**: 手前の歩道、左右のレンガ塀とポスター（固定文で保持。塀・歩道の前には新しい物を置かない）。隣の建物・木・空・山は、新しい物に隠れない部分だけ元のまま
- **空と光**: 季節・時間帯・天候が指定されたときは、空の色と全体の光だけ変えてよい（形・位置は変えない）。指定がなければ元と同じ昼間
- **文字**: 新しい文字・ロゴ・店名は描かない（元のポスターの既存の文字は元のまま）
- **上端**: 生成物の上端を水平に切り落とさず、木の枝先や屋根まで全体を描く。足元は駐車場の地面に自然に接する
- **公園・広場**: セット6にある「公園・広場などの語を場所の名前として書かない」制約は、セット7では置かない（駐車場を広場や庭に作り替えてよい）。様式の形容詞（レトロ・和風 など）の禁止は残す
- **英語の呼び名**: `maskAreaDetail` で「the parking lot in front of the store」と呼ぶよう指示している（英語の見本文は置かない）
- **共通ドラフトとの食い違い**: `app.js` の `buildPrompt()` は「建物…その他すべての建築要素は元の画像のまま保持する」を必ず入れる（変更不可）。「店舗が覆われてもよい」とはルール8・9・固定文で打ち消している。効かない場合は画像で確認して調整する
- **限界**: マスクなし・合成なしのため、保持は固定文だけで担保する。全面が再生成されるので、ポスターの細かい文字がぼやける可能性がある
- **既存動作への影響**: `?set=7` と setId 7 は、これまで既定（セット4）へのフォールバック／`/api/generate-concept` では 403 だった。セット7の追加後は、セット7として動く

### 手前の大きな建物の英文（案B: `foregroundBuildingKeywords` / `foregroundBuildingSentence`）
ホテルなど大きな建物を指定したとき、LLM の出力だけでは建物が店舗の奥や横に描かれやすい。そこで、位置・向き・店舗との重なりをサーバーが固定の英文で付ける。

- **項目**: `IMAGE_SETS[n]` の任意項目 `foregroundBuildingKeywords`（施設名の判定語の配列）と `foregroundBuildingSentence`（挿入する英文）。両方あるセットだけで働く。現在はセット7のみ（判定語: ホテル、ビル、マンション、病院、学校、図書館、美術館、博物館、体育館、庁舎、階建て）
- **判定の対象**: ドラフト1行目 `…を(施設)をメインとした場所にする。` の施設部分だけ。他の行（雰囲気・周辺など）に「ホテル」「ビル」があっても挿入しない。「特になし」でも挿入しない
- **挿入の位置**: 共通ハンドラ（`/api/refine-prompt`）で、連結を `[promptPrefix, foregroundSentence, 中間部 + '.', promptSuffix]` の順にする（`foregroundSentence` が空なら入らない）。項目のないセット1〜6は出力が変わらない（旧実装との出力同一をモックで確認済み）
- **固定文**: `The new main building stands on the front part of the parking lot, just behind the low brick walls, close to the camera, its facade facing the viewer, large in the frame, hiding most of the pink shop behind it.`（アポストロフィは入れない。TS の単一引用符文字列と `call_concept.py` の正規表現のため）
- **LLM への指示**: `maskAreaDetail` の【施設が大きな建物の場合】で、階数・外壁の素材と色（回答にある内容だけ）と、建物の足元は前庭・車寄せ・植栽の地面、の2点だけを書かせる。位置・向き・重なりは固定文が担うので英語では書かせない（ルール9にも明記）

### クリーン画像を mask に使う理由
元写真には、左右に動物の置物がある。これを「撤去してよい」とプロンプトで指示するだけでは、置物が残る・別の物に変わるなど不安定だった。そこで置物を画像加工で消した `007-motogazou-store-clean.jpg` を作り、`mask`（fal.ai に送る画像）だけを差し替えた。`original`（ページ表示用）は元写真のまま。

- **加工範囲**: 左右の置物の周辺だけ（153ブロック、全体の1.61%）。左の雑草・塀・ポスター・歩道・店舗は残す。左は `(160,232,480,560)` を右へ70px・上へ4px、右は `(848,920,456,528)` を左へ64px・下へ1px 動かして周囲の路面をコピーし、右の塀の根元は `x916–919` を `x+6` から複製した
- **範囲外の画素は元画像と完全一致**: JPEG の DCT 係数を、編集したブロックだけ差し替えて保存した（再圧縮しない）。元画像との最大差は0、差のある画素は0（編集範囲の外）。画像を差し替えるときも、この方法で範囲外の一致を数値で確認する
- **プロンプトへの影響**: 置物の撤去文・跡埋め文は `maskAreaDetail` と `promptSuffix` から削除した。英語プロンプトに置物の名前は出ない

### 地面の書き方（asphalt 対策）
施設が広場・公園・庭、または未指定のとき、LLM が `asphalt` や `parking lot surface` と書くと、元の駐車場の舗装が残りやすい。`maskAreaDetail` とルール14で、地面は芝生・小道・植栽で書き、駐車場の舗装を表す語は書かないよう日本語で指示している。大きな建物の場合も、足元は前庭・車寄せの地面とし、駐車場の舗装とは書かない。

### 入口脇の赤い箱と、スタイルの適用範囲
店舗の入口脇の赤いポストは、固定文で「入口脇の細い白い棒に付いた小さな赤い四角い箱（扉の高さの約3分の1）」と肯定形で書いて保持する（否定文は逆効果になりやすいため）。要望のスタイルは「新しく作る物だけに適用し、店舗と付属物（入口脇の赤い箱を含む）には適用しない」とした。

## コンセプト（タイトル・文章）の生成（セット6・7）
6問の回答から、プレゼンシート用の「コンセプトタイトル」と「コンセプト文章」を作り、生成画像のすぐ下（ダウンロード/やり直しボタンの上）に表示する。

- **対象**: `IMAGE_SETS[n].conceptEnabled === true` のセット（セット6・7）。セット1〜5は HTML・`app.js` の動作・既存APIの応答が変わらない（`__IMAGE_SET__` に `conceptEnabled` が出力されず、`app.js` の `isConceptEnabled()` が false のため何もしない）
- **API**: `POST /api/generate-concept`　入力 `{ setId, answers: { facilityType, usageScene, style, surroundings, timeOfDay, additionalNotes } }`
  - 成功: `{ success: true, title, text, meta: { titleLength, titleLengths, titleIndex, titles, textLength, paragraphs, retried, inRange } }`（画面が使うのは `title` / `text` のみ。`meta` の `titleLengths`（3案の字数）・`titleIndex`（選ばれた案の番号、1始まり）・`titles`（3案の全文）・`titleExclusions`（各案の除外理由）・`bannedWords`・`retryReasons` は検証用）
  - `setId` が 1〜7 以外・コンセプト非対応のセットは **403**（OpenAI を呼ばない。`?set=` の既定にはフォールバックしない）。JSON不正・answers 欠落は 400、キー未設定は 500、上流エラー・出力不正は 502
- **モデル**: 定数 `CONCEPT_MODEL`（**`gpt-4.1`**、`OPENAI_API_KEY`）、`response_format: json_object`、初回 temperature 0.7・再生成 0.5、`max_tokens` 900。`/api/refine-prompt` のモデル（gpt-4.1-mini）とは別に管理する。比較（4パターン×2モデル）の結果、字数の安定性と応答時間から gpt-4.1 を採用
- **出力の条件**: モデルは `{"titles": ["案1","案2","案3"], "text": "..."}` を返す。タイトルは切り口の違う3案で、各案 15〜20字（目標17字前後・句読点込み）。文章は 150〜200字（改行を除く）・3〜4段落・敬体。場所は「池田のサカエマチ2番街」と書き、商店街であることは文中で自然に表す。回答にない事実・英語・他地域名は入れない
  - タイトルの質: 自然な日本語にし、「冬朝」「夏夕暮れ」のような一般的でない造語を使わない（「冬の朝」「朝陽」「夕映え」などはよい）。回答の言葉を並べるだけにしない。タイトルに地名（池田、サカエマチ2番街）を入れない
  - 【守ること】: 施設から連想される品物・音楽・催しなど、回答にない具体物を足さない（様子は光・空気・人の気持ちで表す）。文章は第1段落も含め「これから生まれる場所」として書き、今の商店街の様子（人が行き交っている、暮らしを支えている、など）を述べない。回答が指定なしばかりのときは、アーケードの通りがこれからどんな場所になれるかを光・空気・人の気持ちで書く。回答にない「歴史」「伝統」「老舗」「多世代」や、地域の人々の数・属性は書かない
- **タイトルの選択**: サーバーが3案を `Array.from` で数え、次の除外条件に当たる案は選ばない。
  - 除外条件: 季節語（春・夏・秋・冬）と時間帯語（朝・昼・夕・夕暮れ・夕方・夜）の直結（冬朝・夏夕暮れ・冬夜。「冬の朝」は対象外）／地名（池田・サカエマチ）／英字／半角・全角スペース（ひと続きの題にする）
  - 選び方: 「15〜20字」かつ「除外条件なし」の最初の案。なければ、除外条件なしの案のうち17字に最も近いもの。全案が除外条件に当たるときだけ再生成する
  - 各案の除外理由は `meta.titleExclusions`（`seasonTime` / `place` / `latin` / `space`）に記録する
- **検査と再生成**: 文字数は `Array.from(str).length`（文章は空白・改行を除く）。「15〜20字かつ除外条件なし」の案が1つもない、または文章が範囲外・選ばれたタイトルか文章に英字2文字以上が混入・「川西」を含む・文章が改行のない1段落だけ（2段落以上は再生成の条件にしない。段落数は `meta.paragraphs` に記録）・文章に「歴史」「伝統」「老舗」「多世代」を含む（回答に含まれている語は除く）場合は、前回の3案の字数・文章の字数・直し方の具体的な量（例:「どの案もあと4字ほど増やし、17字前後にしてください」）を伝えて **1回だけ** 再生成する（再生成の理由は `meta.retryReasons`）。再生成後も範囲外なら、範囲に近いほうをそのまま返し、`console.log` に文字数を残す（画面は止めない）。JSON不正・項目欠落は失敗扱い
- **「特になし」の扱い**: 10字以下で、なし/ない/なんでも/特に/とくに/任せ を含む回答だけ「指定なし」として渡す（長い回答は誤判定しない）
- **systemPrompt に例文は入れない**（LLM が言い回しをそのまま写すため）。段落ごとの文字数の目安と、タイトルの作り方の手順で指示する。検証で再生成後も範囲外が半数以上なら、検証用と別の例を1つだけ足す案がある
- **画面（`app.js`）**:
  - `generateImage()` の開始時に `requestConcept()` を await せずに呼ぶ（画像の生成・表示は待たせない）
  - `#concept-box` は `#resultActions` の直前に動的に挿入し、画像の表示と同時に見せる。作成中は「コンセプトを作成中…」、失敗・タイムアウト（60秒）は「コンセプトを作成できませんでした」の1行のみ
  - 表示は `textContent` のみ。`displayResult()` のスクロールは、コンセプト欄がある場合も従来と同じ画像の見える位置（ボタン下端が画面下端になる位置）に合わせる
  - 「同じ回答で生成する」の再試行では、同じ回答で作成済み・作成中ならコンセプトを再リクエストしない
  - `resetChat()` で `#concept-box` を削除し、進行中のリクエストの応答は破棄する（世代番号 `conceptRequestId`）
- **セットごとの出し分け（`conceptTheme`）**: systemPrompt の舞台・場所の言い方・地名の扱いは `CONCEPT_THEMES`（`arcade` = セット6、`store` = セット7）で切り替える。セット6（`arcade`）の systemPrompt と検査は従来のまま（基準とバイト一致を確認済み）。
  - セット7（`store`）: 舞台は「川西にある店舗の前の駐車場」、場所の表記は `conceptPlace: '川西の店舗前'`。「商店街」「アーケード」の語は **systemPrompt の文面で避けるよう指示するだけ**で、再生成の検査には加えていない。
  - 検査の違い: セット6は本文・タイトルの「川西」で再生成（`kawanishi`）。セット7は「川西」を許可し、タイトルに「川西」を含む案を除外（`place`）、タイトル・本文に「池田」「サカエマチ」を含むと再生成（`otherPlace`）。
- **変更時の確認**: セット1〜5で `/api/generate-concept` が呼ばれず `#concept-box` が出ないこと、setId 1〜5・不正値で 403 になることを確認してから本番に出す

## データフロー
```
ユーザー入力 (6問)
  → buildPrompt() → 日本語ドラフト（maskMode で冒頭表現を切り替え）
  → shouldSkipComposite() 判定
  → refinePrompt() → POST /api/refine-prompt → GPT-4.1-mini → 英語プロンプト
      （セット6のみ: promptPrefix + LLMの中間部分 + promptSuffix をサーバー側で連結して返す）
  → POST /api/generate-submit → fal.ai キュー投入（aspect_ratio はセット値） → requestId
  → ポーリング GET /api/generate-status (3秒間隔・最大360秒)
  → GET /api/generate-result → imageUrl
  → compositeWithOriginal() → Canvas合成 → blob URL
  → displayResult() → タブUI表示・ダウンロード有効化
（セット6のみ: generateImage() の開始時に POST /api/generate-concept を並行で呼び、画像の下にコンセプトを表示）
```

## 使い方
1. ページを開くと AI からの最初の質問が表示される
2. 6つの質問に答える（「特になし」「お任せします」などでスキップ可）
3. 画像生成が開始（通常1〜2分）
4. 生成完了後、タブで「元画像」「生成結果」を切り替えて確認
5. 「画像をダウンロード」で保存、「もう一度やり直す」でリセット

## 新しい画像セットを追加する手順
1. 元画像を `public/static/images/` に配置する。`aspectRatio` に指定する比率と実寸を合わせておくと合成時のずれがない（例：16:9 なら 1700×956）
2. `IMAGE_SETS` に新しいIDのエントリを追加する。`maskMode: 'none'` の場合は `original` と `mask` に同じファイル名を設定する
3. `maskAreaDetail` に、生成対象範囲・保持すべき背景要素・禁止事項を記述する。英語の見本文や具体例は、LLMが回答にない場合でも出力に写すことがあるため、必要最小限にする（セット6は日本語の指示のみ。「セット6の仕様」参照）
4. `compositeCutRatio` は、保持したい背景の下端と生成物の上端の間に来るよう設定する。まず低層の施設で生成し、切り落としが起きたら値を下げる
5. 動作確認は `?set=新しいID` で行う。既定にする場合は `config/image-set.json` の `IMAGE_SET_ID` を変更し、`npm run build` してデプロイする
6. `maskAreaLabel` は `buildPrompt()` の日本語ドラフトに入り、`shouldSkipComposite` の判定対象になる。`app.js` の `NIGHTTIME_KEYWORDS` / `SKIP_KEYWORDS_EXTRA` の語（アーケード・提灯・夜・ドーム・大屋根 など）を含めないこと。`sceneDescription` / `maskAreaDetail` / `edgeTreatmentRule` は systemPrompt 側に入り判定対象外
7. 空・光を時間帯に合わせて変えたいセットは、`systemPromptRuleOverrides`（ルール 1 / 2 / 3 / 4 / 8 / 9 / 10 / 12 / 13 / 14 のうち必要なもの）と `timeOfDayNote` を指定し、`maskAreaDetail` に「空は元画像のまま」と書かないこと（指定がない場合に限り元画像の昼間の空と光を維持する、という書き方にする）。看板などの色は「元の色を保ち、光による色味の変化のみ許可」と書く
8. 看板・屋根・カメラなど毎回保持させたい構造は、`promptPrefix` / `promptSuffix` の固定文として持たせ、LLMには中間部分だけを書かせる。固定文と同じ内容を systemPrompt に英語で書かないこと（中間部分に重複して出る）
9. 空の演出（花火など）は「ユーザーの回答に明記されている場合だけ描く」と日本語で書き、systemPrompt に具体的な演出名の英語例を置かないこと
10. 新しいセットを本番に出す前に、`?set=` を付けない既定（セット4）の表示・動作が変わらないことを確認する（HTMLが現行の本番とバイト一致するか、`?set=` 未指定・不正値でセット4になるかを見る）

## 既知の課題
- `app.js` の `buildPrompt()` に「建物、道路、通路、高架構造物、その他すべての建築要素は元の画像のまま保持する」という固定文があり、セット4の「新設する構造物は病院建物の手前に重なってよい」という指示と論理的に競合する。現状は GPT-4.1-mini が解決しているが、生成物が不自然に小さくなる・奥に配置される事象が出た場合はここが原因候補
- `public/static/images/` に未使用の白塗り画像が残っている
- セット6: 「レトロ」「モダン」など様式の形容詞が施設名の前に付く英語（例: `retro-style cafe area`）が出力に残ることがある。systemPrompt で禁止しているが、LLMが守らない場合がある。今のところ生成結果への悪影響は見つかっていない
- セット6: 看板の面に生成物が重ならないことは、プロンプトでの指示のみで担保している。重なる場合の対策として、看板部分を元画像から貼り戻す合成が考えられるが、未実装
- セット7: 大きな建物（ホテル等）を指定すると、駐車場の手前に建つのではなく、店舗そのものが建て替えられた画像になる場合がある。案B の固定文で位置を指示しているが、保証はできない（現状は許容）
- セット7: カフェなどを指定したとき、店舗の庇や窓に日よけなどの飾りが加わる場合がある。「店舗と付属物にはスタイルを適用しない」と指示しているが、完全には防げない（許容）
- セット7: 様式の形容詞（`a western-style hotel` など）が施設名の直前に混入することがある（ルール12違反）。生成結果への悪影響は見つかっていない。セット6と同じ現象
- セット7: コンセプトのタイトルの字数にばらつきがある（目標の17字前後から外れた案、14字など、が選ばれることがある）。検査の範囲内なら再生成しない
- Q6 の入力例文（`app.js` の質問文）に「空には花火があがっている」があり、全セット共通で表示される。セット6でこの例文が回答の誘導になる可能性がある（プロンプトには入らない）
- セット6: 暴走ガード（100語超または同じ句3回以上で再試行し、70語に切り詰め）は、実APIで作動したことがまだない。作動時のログは静的Pagesの `wrangler pages deployment tail` では見えないため、動作の確認はモックによるものだけ
- セット6: LLMが書く中間部分が、66語の上限を超えることがある（実測で67〜71語）。ガードは100語超から作動するため、この程度は通る。生成結果への悪影響は見つかっていない
- セット6: 回答にペットがあっても、画像にはっきり出ないことがある
- セット6: コンセプトのタイトルに、似た言い回し（「ぬくもりに包まれる」）が繰り返し出ることがある

## デプロイ
- **プラットフォーム**: Cloudflare Pages
- **プロジェクト名**: machizukuri-ai
- **ステータス**: ✅ 本番稼働中
- **技術スタック**: Hono + TypeScript + fal.ai NanoBananaPro + OpenAI GPT-4.1-mini
- **デプロイ履歴**: Cloudflare ダッシュボードで確認する

### デプロイ方式
Git 連携なしの手動デプロイ。`main` への push・マージでは自動デプロイされない。

```bash
# 本番（main の内容をビルドしてから）
npm run build
npx wrangler pages deploy dist --project-name machizukuri-ai --branch main

# プレビュー（別ブランチ名を付ける。本番には影響しない）
npm run build
npx wrangler pages deploy dist --project-name machizukuri-ai --branch set6-test --commit-dirty=true
```

- プレビューは `https://<ブランチ名>.machizukuri-ai.pages.dev`（ブランチ名のエイリアス）と、デプロイごとの `https://<デプロイID>.machizukuri-ai.pages.dev` で開く
- 本番にしたいブランチ名は Cloudflare Pages の本番ブランチ設定（`main`）で決まる。`--branch main` 以外は本番にならない
- 以前のデプロイへ戻す場合は、Cloudflare ダッシュボードの Deployments で確認・操作する

### 開発の進め方（セット追加など）
1. 機能ブランチで開発する（例: `feature/set6-sakaemachi`）
2. ビルドして、プレビュー用のブランチ名でデプロイし、`?set=N` で確認する
3. GitHub で PR を作り、Create a merge commit でマージする
4. マージ後に、`main` を本番へ手動デプロイする
